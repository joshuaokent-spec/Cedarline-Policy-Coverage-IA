# IA Validation Plan

This rapid portfolio project does not claim completed card sorting or tree testing.

A production validation plan would use several methods because each answers a different IA question.

## 1. Open card sort

**Goal:** learn how participants group policy types, service tasks and educational topics in their own language.

Representative cards:

- Auto insurance
- Homeowners
- Renters
- Umbrella
- Proof of insurance
- Pay a bill
- Report a claim
- Track a claim
- Roadside
- Discounts
- Deductible
- Coverage limits
- Policy documents
- Find an agent

Outputs would inform category labels and grouping hypotheses.

## 2. Tree test

Test the proposed text-only hierarchy with tasks such as:

- You need proof of insurance for a new car. Where would you go?
- Your basement has water damage and you want to understand possible coverage. Where would you look?
- You want to see whether your current claim has an assigned representative.
- You are renting an apartment and want to understand what insurance protects your belongings.
- You want to understand what a deductible means before reviewing a policy.

Metrics:

- task success;
- directness;
- first-click path;
- backtracking;
- time to destination.

## 3. Task-based prototype test

Use the visual prototype to test whether navigation and search work together.

Observe:

- whether participants begin with navigation, task shortcut or search;
- terminology mismatches;
- whether coverage-page headings match user expectations;
- whether people confuse product shopping and policy-management tasks.

## 4. Accessibility validation

Review:

- keyboard operation of menus;
- mobile menu structure;
- landmark and heading hierarchy;
- focus visibility;
- search result announcements;
- zoom/reflow;
- whether mega-menu grouping remains understandable without visual layout.

## Decision rule

The proposed IA should be revised based on observed failure patterns, not protected because it “looks organized.”
