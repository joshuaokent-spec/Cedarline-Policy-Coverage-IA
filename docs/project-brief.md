# Project Brief — Policy & Coverage Information Architecture

## Design challenge

Insurance websites contain a mixture of product categories, individual policies, coverage explanations, discounts, claims information, billing tasks, account tools, agent information and educational content.

Users often arrive with a real-world question rather than the correct insurance vocabulary.

Examples:

- “Does my policy cover a burst pipe?”
- “Where do I get my insurance card?”
- “Do I need renters insurance?”
- “What protects expensive jewelry?”
- “How do I check my claim?”
- “What is an umbrella policy?”

The IA challenge is:

> **How should insurance information be organized so people can find the right answer without already knowing which insurance term or organizational department owns it?**

## Primary user needs

This project assumes several common information-seeking modes:

1. **Protect something** — car, home, belongings, family, business.
2. **Complete a task** — pay, download, change, report, track.
3. **Understand coverage** — “would this situation be covered?”
4. **Learn a term** — deductible, liability, endorsement, limit.
5. **Talk to someone** — agent, claims representative, support.

These are IA hypotheses, not research findings.

## Design principles

### Organize around user intent
Product taxonomy should not be the only way into the site.

### Preserve formal terms without requiring them
Insurance terminology still matters, but plain-language labels should help users reach it.

### Separate products from service tasks
“Auto insurance” and “download proof of insurance” serve different mental models.

### Provide multiple paths to the same answer
Search, task shortcuts, navigation and contextual links can converge on the same content.

### Use strong information scent
Navigation labels should help a user predict what is behind them.

### Keep the sitemap explainable
The structure should be understandable enough to test with a tree test and maintain across teams.
